# Contributing

Thanks for wanting to help with NullModem BBS. Issues (bugs, ideas) and
pull requests are welcome.

## Building

The BBS uses [nullmodem-kit](https://github.com/midrei/nullmodem-kit)
(ANSI/CP437, QWK, Zmodem). Go fetches it like any other module; to work
on both at once, clone them side by side and use a `go.work`:

```sh
git clone https://github.com/midrei/nullmodem-bbs
git clone https://github.com/midrei/nullmodem-kit
go work init ./nullmodem-bbs ./nullmodem-kit
```

Then, in `nullmodem-bbs`:

```sh
go vet ./... && go test ./...          # the Go side
cd web && npm ci && npm run check       # the web side
docker build --build-arg COMMIT=$(git rev-parse --short HEAD) -t nullmodem-bbs .
```

The Zmodem tests run against Synchronet's `sexyz` when it's installed
and are skipped otherwise (see [docs/building-sexyz.md](docs/building-sexyz.md)).

## Conventions

- **Texts in every language.** The board speaks English (`en`), German
  formal (`de`) and German informal (`de-du`). Every new user-visible
  text -- Telnet, portal, reader, admin, API errors -- goes into
  `internal/i18n/lang/en.yaml` and `de.yaml` (and `de-du.yaml` where the
  Du form differs). `go test ./internal/i18n` checks completeness. German
  uses Swiss spelling (ss, not ß). If you don't speak German, add the
  English text and say so in the pull request.
- **Docs in both languages.** Sysop/user docs exist as `docs/x.md` and
  `docs/x.de.md`; a change updates both (same caveat as above).
  Developer docs are English only.
- **Telnet screens fit 79 columns** (an 80-column terminal wraps a full
  line). The stock screens are generated by `scripts/screens/space.py`
  -- change the generator, not the `.ans` files.
- **Commit messages in English**, describing what changed and why.
- **Go:** wrap errors with context (`fmt.Errorf("...: %w", err)`), don't
  drop them silently, and keep protocol handlers apart from storage.

## Pull requests

Keep a pull request to one thing; CI runs the Go tests and the web
checks on it. For bigger changes, open an issue first so we can agree
on the approach before you put time in.

## Security

Please don't report vulnerabilities as issues -- see [SECURITY.md](SECURITY.md).
